# v81 — 기존 탐사를 유지하는 성능 최적화

사용자의 요청은 렉 개선입니다. 전투 난이도·몹 수·성장·보상·발사 간격·난수 호출을
바꾸거나 애니메이션을 줄여서 성능 수치를 올리지 않습니다. 프레임 제한도 추가하지 않습니다.
정확한 이전 루트는 `dungeon80.html`에 보관합니다.

## 구현

- `dungeon81-cache.js`: 큰 원본 시트 대신 요청한 **전신 셀 전체**를 원래 픽셀 크기로
  CPU 캔버스에 한 번 복사합니다. 가능하면 작은 ImageBitmap으로 보관하고, 불가능하면
  CPU Canvas를 사용합니다. 캐시에 GPU 캔버스를 쓰면 큰 원본을 매번 업로드하는 역효과가
  있어 `willReadFrequently`를 사용합니다. 원본 파일/메타데이터/발/반전/발사점은 그대로입니다.
- 최초 CPU 소스 준비를 이미지 로딩 중 처리합니다. 네트워크 오류/디코드 실패는 게임 시작을
  막지 않고 기존 원작 idle/poster/도형 대체 경로를 사용합니다. 기존 9초 시작 안전장치 유지.
- 셀/텍스트 캐시의 **추가 픽셀 버퍼 예산은 24MiB, 최대192개**입니다. LRU 제거 시 Bitmap을
  close하거나 Canvas 크기를0으로 만듭니다. 이것은 전체 브라우저/GPU 메모리 측정값이 아니며,
  원본 이미지의 이론상 decoded218MiB가24MiB로 줄었다는 뜻도 아닙니다.
- 배경·느려지는 지면·방 고정 광원은 현재 방 하나만 실제 화면 해상도에 맞춰 캐시합니다.
  방/크기/DPR/원본 로드 상태/지면 좌표가 달라지면 재생성합니다. 문·파괴물·적·탄환·예고는
  계속 실제 상태에서 그립니다. 지도는 보이는 방/방문/클리어/현재 위치/글꼴 상태가 변할 때만 갱신.
- HUD는20Hz, 입력/메뉴/단계 전환은 즉시 반영합니다. 시뮬레이션과 애니메이션은 여전히 매 rAF.
  초상화 같은 같은 URL 재할당, DOM 재탐색, 플레이 중 숨은 메뉴 JSON 생성, 중복 pickup 계산 제거.
- `dungeon81-nav.js`: 방의 실제 장애물과 bounds가 바뀌지 않으면 그래프 키를 다시 조립하지 않습니다.
  가장 가까운 보이는 노드는 거리의 반복 계산/전체 정렬 대신 같은 hypot·기존 순서의 안정적인
  최소 후보 탐색으로 찾습니다. 경로 역순 복사도 제거합니다. 장애물 파괴/추가/이동 시 무효화.
- `dungeon81-engine.js`는80 엔진과 **일반 적 steer import만 다릅니다**. 보스/바이옴/투사체/
  방 생성/성장/경제/저장 검증은80 그대로 사용합니다. 복사본 동기화는 소스 동등성 검사로 보호합니다.

## 저장/그림 보존

동일한 `butter.dungeon80.v1`과 음량 키를 사용합니다. 새 저장 버전/마이그레이션/무료 회복은 없습니다.
기존80에서 일시정지한 탐사를81에서 이어갈 때 전체 상태가 정확히 같음을 브라우저로 검사합니다.
80 진단의 기존 해시도 유지하며, 예전 index 해시는 `dungeon80.html`에서 확인합니다.

원작 파일을 축소/재생성하지 않습니다. 64개 idle/walk/shoot/high/gun/walkGun/반전 상태의
전체 셀을 정수 원본 배율에서 비교하여 RGBA 차이0을 확인합니다. 실제 게임의 소수점 발 기준·
80배율·화면 DPR은 그대로지만, 이미지와 Canvas/Bitmap의 브라우저 보간 커널은 다를 수 있습니다.
즉, 실제 화면 모든 픽셀이 동일하다는 주장은 아닙니다. 잘림이나 새 리그/팔다리 왜곡은 추가하지 않습니다.

## 재현과 검증

`npm test`: 기존 규칙 + 같은 입력의80/81 상태/RNG 완전 동등 재생,48개 전투방의 여러 반경 경로,
장애물 파괴/추가/이동, 캐시 예산/적중/제거/CPU fallback. 기존 원작/승인 그림 검사도 실행합니다.

`tools/check-dungeon81-browser.mjs`: 실제 시작·사격·정확한 이어하기, 수업/액티브/보스/큰 방 fixture,
390/568 모바일 양손 입력·동작 줄이기·이미지/저장 실패. 보관80 브라우저도 별도 검사합니다.
`tools/check-dungeon81-cache-browser.mjs`: 기존80→81 정확한 저장, 전체 셀64개, DPR2 리사이즈.
`tools/playtest-dungeon81.mjs`: 전체 상태를 읽는 정책이지만 실제 DOM/키보드/마우스로만3방 진행.
위치/HP/아이템 주입이 없는 실제 입력 검사이며 사람의 재미 평가가 아닙니다.

`tools/check-dungeon81-performance.mjs`: 같은 lag80 시드·1366×850·DPR1·7초 첫 전투 진입을
80/81 각각3회, 순서를 바꿔 **매번 새 Chromium 프로세스**에서 비교합니다. 전투방/무적 fixture이며
CPU profiler/CPU throttle/동시 테스트를 사용하지 않습니다. 정지한120회 렌더의 CPU 제출 시간은
별도 항목이고 실제 GPU 페인트 시간이나 FPS와 같지 않습니다. 사용자의 장치에서 잰 값도 아닙니다.
이전의‘42FPS/200ms’와 실험 조건이 완전히 같다고 주장하지 않고, 이번 짝비교끼리 비교합니다.

측정 원자료와 최종 소스 해시는 `dungeon81-performance.json`에 기록합니다.

최종3쌍 측정: 최대 프레임 간격의 최악값266.6→116.7ms,33.4ms 초과 프레임 합계16→6,
50ms 이상 Long Task 합계10→0. 평균 프레임 간격의 중앙값17.79→17.02ms입니다.
120회 정지 렌더 CPU 제출 시간 중앙값805.4→17.0ms. 이는 GPU 전체 페인트나 사용자 장치
FPS가98% 좋아졌다는 뜻이 아닙니다. 초상화 src 재설정은 세 측정 합계1199→0회입니다.
실제 입력3전투방/12처치/35.3903초/남은HP60, 상태 주입 없이 진행했습니다.
