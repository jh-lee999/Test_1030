# v82 — 수동 조준, 지연 추적, 적중 후 무작위 도탄, 나무상자 적중 수정

사용자가 명확히 지정한 동작: ‘추적 효과도 내가 쏜 방향으로 나간 뒤 추적하고,
도탄은 먼저 맞힌 다음 임의 방향으로 퍼져야 한다.’ 아래 수치는 팬게임의 구현값이지
아이작 원작 코드를 가져오거나 정확한 원작 수치라고 주장하는 것이 아닙니다.

## 발사/추적/도탄

- 기본 평타/저학년 도탄탄은 수동 조준 방향으로 출발하며 적을 골라 발사 방향을 바꾸지 않습니다.
  기존 마우스 좌표·방향키·두 터치 스틱과 원작 발사점/발사 타이밍은 유지합니다.
- 추적 유물은 최초0.12초 직진 후 전방의 보이는 적만 대상으로 최대1.9rad/s로 완만하게 꺾입니다.
  뒤의 적이나 불투명 엄폐 너머의 적을 향해 즉시 되돌아가지 않습니다. 빔/근접의 기존 피해+10% 유지.
- 저학년/낫 도탄탄은 **실제 적중 때만** combatRng로0..2π의 새 방향을 뽑습니다.
  다음 적을 고르거나 적이 없다는 이유로 사라지지 않습니다. 기존 유한 적중 예산(1+저학년,
  낫 최소4)·수명·탄환 상한은 유지. 같은 적에0.12초 재적중 방지, 다른 적을 막는 전역 잠금 제거.
  추적 유물과 조합하면 도탄 직후에도0.12초는 새 방향으로 날아간 뒤 다시 추적합니다.
- 무작위 도탄은 전투 RNG만 소비합니다. 상자/유물/경제 RNG는 사용하지 않으며, pause/메뉴에서는
  비행·추적 지연·무작위 추첨이 모두 멈춥니다. 학년/유물 설명도 실제 새 동작과 맞춥니다.

## 상자 버그와 수정

기존 코드는 탄환의 ‘막히지 않음→막힘’ 전환만 검사했습니다. 발사점이 이미 상자 안에 있으면
검사를 건너뛰고, 큰 탄의 첫 접촉에는13px 반경을 쓰면서 상자를 찾을 때는 고정10px를 써서
탄만 사라지고 상자는 남았습니다. 빔/근접에는 상자 파괴 호출이 없었습니다. 네 경우 모두 재현했습니다.

`dungeon82-collision.js`의 선분-AABB 검사는 이동 전체에서 가장 먼저 닿은 엄폐와 정확한
동일 반경을 사용합니다. 나무상자는 CRATE alpha bounds/공유 배율에서 보이는 윗면까지 판정합니다.
움직임/AI는 기존 발밑 footprint와81 길찾기를 유지하고, 양 팀 탄환/시야 판정은 같은 상자 박스를 씁니다.
상자 그림은 새로 그리거나 확대하지 않습니다. 이미지 실패 시 나무상자 도형도 같은 박스를 사용합니다.

- 평타/권총/부채/차지/귀환/분열탄: 빠른 관통 이동, 가장자리, 안쪽 발사도 상자를 파괴.
- 빔: 첫 엄폐에서 멈추며 해당 나무상자만 파괴. 거울 반사/전체 사거리 예산 유지, 큰 방 실제 bounds 사용.
- 근접: 전방 사거리 내 보이는 상자 파괴. 뒤/범위 밖/단단한 벽 뒤의 상자를 파괴하지 않음.
- 왕짱돌: 지나간 경로의 상자를 부수고 계속 관통. viewport 반사와 남은 수명은 그대로.
- 바위/틈새를 평타로 부수지 않고, 황금상자는 쏴서 열 수 없음. F/열쇠1 규칙과 나무3%/황금30% 유지.
  hp=0 커밋 뒤 한 번만 보상 추첨하므로 다중 탄·빔·재방문에서 중복 보상 없음.

저장됩니다. 기존 큐를 지우거나 HP/충전/성장을 초기화하지 않습니다. v81 정확한 루트는 dungeon81.html.
